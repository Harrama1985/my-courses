1

🎯 شنو كنتعلمو؟

AI Engineer كياخد foundation model جاهز (بحال GPT) وكيحوّلو لـ feature فـ app تقدر تعتمدي عليها. الخدمة ديالك: context، tools، evals، و reliability. الـ training ديال الـ model ماشي خدمتك.

2

🤔 علاش محتاجاه؟

نتي ديجا كتبني واجهات بـ React. الـ repo ai-engineering-fundamentals كيعطي نفس الفكرة فـ project واحد: canvas ديال Excalidraw + chat. فالأول الـ chat ما كيدير والو. من بعد كيولي agent كيرسم.

إلا بقيتي غير كتنادي الـ API وكتحكمي بالعين، ما عندكش طريقة تعرف واش الـ change نفع.

3

🧠 شرح دارجة

الـ model كيقرا text وكيرجّع text (أو قرار: «عيّط لهاد function»). ما كيشوفش الـ canvas بوحدو، وما كيرسمش بالماوس. نتي كتعطيه: شنو بغى الـ user، شنو كاين فالـ canvas، وشنو الـ tools المسموحة.

الـ tool هنا function عادية عندها schema واضح. مثلاً «زيد rectangle و label». الـ code ديالك هو اللي كيرسم فـ browser. الـ model غير كيختار الـ tool وكيعمّر الـ fields.

ومن بعد كتقيسي: نفس الـ questions، كل مرة، وكتشوفي الـ score طلع ولا هبط. هاد الحلقة هي الـ course كامل: Build → Eval → Improve → Eval.

6

🔍 الخطوات فدماغك

  1. الـ user كتبّات message، ماشي code.
  2. الـ message تمشي للـ agent على الـ server. الـ key ما يبقاش فـ browser.
  3. الـ model يختار tool، ما يرسمش pixels.
  4. الـ code ديالك يحوّل نتيجة الـ tool لـ elements على الـ canvas.
  5. من بعد، نفس الـ message تدخل فـ eval باش تعرفي واش الـ version الجديدة حسن.

7

💻 code صغير

هاد الـ shape هو root ديال الـ app فبداية الـ repo. جوج components React كتعرفيهم. الجديد هو شنو غادي يوقع من بعد Send. 

export default function App() {
  return (
    <div className="app">
      <Canvas />       {/* canvas. خدام اليوم */}
      <ChatPanel />    {/* chat. Send باقي فارغ */}
    </div>
  );
}

ملي الـ user يطلب diagram، الـ model ما كيرجّعش image. كيرجّع data بحال هادي، والـ code ديالك كيرسمها:

{
  "type": "rectangle",
  "label": "User"
}

بحال setState: نتي ما كترسميش الـ pixel. كتعطي الـ data، و React / الـ canvas كيرسمو.

8

⚛️ مقارنة مع React

اللي كتعرفيه فالـ agent
الـ component كيرجع JSX الـ model كيرجّع قرار: أي tool، وبأي fields
ما تحطّيش secret key فـ client الـ call للـ model كيمشي من الـ agent، ماشي من الـ chat
tests على function ثابتة evals على examples، حيت الـ response ما كيبقاش بحال بحال كل مرة

🌍 example واقعي

الـ user كتبّات:

draw a sequence diagram of an OAuth login

شنو خاص يوقع، بالترتيب:

  1. الـ chat يبعث الـ message للـ agent.
  2. الـ model يفهم: خاصو rectangles (User, App, Provider) و arrows بيناتهم.
  3. ينادي tool «زيد elements»، ما يقولش غير «ها diagram زوين».
  4. الـ canvas يورّي الـ arrows. إلا مسحات كلشي بلا confirmation، هاديك غلطة ثقة — غادي نصلحوها من بعد بـ approval.

إلا بدّلتي الـ prompt والـ canvas وعدد الـ tools فنفس النهار، ومن بعد الـ diagram تحسّن، ما عرفتيش شنو اللي نفع. change واحد، من بعد eval.

14

🔄 Recap

الـ repo كيبني app ديال الرسم: canvas + chat. الأيام اللولة: الـ agent يخدم، الـ chat يتوصّل، والـ eval يعطيك رقم أساس. من بعد كل lesson كيحسّن حاجة وحدة وكيعاود الـ eval.

المبادئ اللي غادي نرجعو ليهم جاية من 12-Factor Agents: الـ tool هي function، الـ context ملكك، والـ eval هو test ديال السيستيم.

15

🎯 شنو تتذكّري

  1. الـ model محرّك جاهز. نتي كتركّبي الطوموبيل.
  2. الـ diagram = data ديال elements، ماشي image من الـ model.
  3. Build، من بعد Eval، من بعد change واحد.

إلا «agent» باقي ضبابي، كتبي الـ message اللي ما دخلاتش. نعاودوها برسم أصغر.
